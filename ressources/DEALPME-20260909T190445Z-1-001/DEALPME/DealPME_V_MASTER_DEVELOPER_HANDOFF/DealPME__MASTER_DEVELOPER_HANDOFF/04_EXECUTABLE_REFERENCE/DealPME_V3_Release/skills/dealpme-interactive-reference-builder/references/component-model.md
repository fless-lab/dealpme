# Component model

Use shared components/data renderers rather than one-off page copies.

- App shell: demo banner, header, hero, tabs, footer CTA.
- Access simulator: dev-only.
- Overview: information keys, evidence-oriented highlights, KPIs, trajectory.
- Financials: charts plus P&L/balance sheet/cash flow tables.
- Transaction: structure, buyer profile, CTAs, stage timeline, process notes.
- Risks: structured risk cards with evidence links.
- Documents: search/filter/list/viewer.
- Q&R: filter, threads, document links, create-question flow.
- VDR: folder tree, document list, viewer, metadata, Q&R, download control.
- Modal/toast system: explicit blocked/success states.

Keep UI controls code-native. Keep synthetic document content as fixture data/files, not raster screenshots.
